# 课程资料下载区（2026-10-27）

「为什么打不开我的课程资料」的解法：课件以前只列文件名、点了没反应（当时定的是「只做索引，文件不上站」）。现在把服务器上有文件的课件做成**登录后可下载**。

## 现在的样子

- `/courses` 里每张课程卡展开后，「课件」清单每条都是链接，右侧标体积；点开新标签页下载
- 首次点会弹浏览器的登录框：**用户名 `doupi`**，口令见对话（也可以自己改，见下）
- 没有文件的条目保持灰色（`li.off`），鼠标悬停提示「本地有记录但文件没下载到」
- 卡片右上角标签从「N 份课件」改成「N 可下载」，一眼看出哪些课真能下

## 服务端怎么做的

不经过 Halo（Halo 的附件接口对这个 PAT 全 403，且主题资源走的是 nginx）：

1. 文件放宿主机 `/opt/1panel/www/course-files/<课程>/<文件名>`（容器里是 `/www/course-files/…`）
2. vhost `/opt/1panel/www/conf.d/doupi123.top.conf` 里加：

```nginx
location ^~ /course-files/ {
    auth_basic "doupi course files";
    auth_basic_user_file /www/.htpasswd-doupi;
    alias /www/course-files/;
    autoindex off;
    charset utf-8;
    add_header Cache-Control "private, max-age=0";
}
```

3. 口令文件 `/opt/1panel/www/.htpasswd-doupi`（`openssl passwd -apr1` 生成，容器里没有 `htpasswd` 命令）
4. `docker exec 1Panel-openresty-qKv1 nginx -t && nginx -s reload`

工具：`probe/serve_course_files.py`（`conf` 写配置并 reload，`verify` 检查 401/200）。

去重后 `courses.js` 里是 696 条文件记录、**438 份可下载**（21 条是同名重复行）。

重新生成：`python -u probe/build_courses_data.py`（把 `files` 从字符串数组换成 `{n, ok, sz}`，可下载的排前面、按体积降序）。

## 上传

`probe/upload_course_files.py`：SFTP 逐份上传，**服务器上已存在且大小一致就跳过**，支持 `--plan` 只看清单、`--limit 3` 测速。

```powershell
$env:PYTHONPATH = (Resolve-Path '.deps').Path
python -u probe/upload_course_files.py --plan      # 清单
python -u probe/upload_course_files.py             # 全量（可断点续传）
```

实测上行 ~1 MB/s，459 份 / 1.6 GB 约 28 分钟。

## 改口令

```bash
# 在服务器上
NEW='你的新口令'
printf 'doupi:%s\n' "$(openssl passwd -apr1 "$NEW")" > /opt/1panel/www/.htpasswd-doupi
```

不用 reload，basic auth 每次请求都读文件。

## 还没做的
