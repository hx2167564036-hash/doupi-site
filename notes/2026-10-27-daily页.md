# /daily 时间轴页

`mockups/v4/daily.html` —— 单文件、无依赖，双击即可看。数据在构建时就注入，运行时不再请求接口。

## 结构

| 区块 | 内容 |
|---|---|
| 头部 | `492 篇，从 2025-04-09 写到 2026-10-08；一共 548 天，其中 476 天有字，72 天留白` |
| 热力条 | 76 周 × 7 行，周一起列；有字 `#1D1D1F`、留白 `#E9E9EE`；`title` 显示日期 |
| 左栏（sticky） | 搜索（`2026-08` / `08-04` / `476` / `day 476` 都能命中）+ 19 个月索引，按年分组，右侧是篇数 |
| 时间轴 | 年 → 月分块；**一天一行**：`08-04 周二 [Day 477]`，同一天多篇时并列多个 chip |
| 留白标记 | 相邻两天差 > 1 时插一行 `留白 N 天`（两侧细线，居中 mono 小字） |
| 外链 | 每个 chip 指向 `https://doupi123.top/archives/<slug>`，新窗口打开 |
| 月份头 | sticky 到 `top:58px`，大号月份 + `2026 · 10 天 / 10 篇` |

## 数据管道

```
mockups/v1/data/posts.json          （492 条：day / date / title / slug，来自 Halo 内容 API）
        └─ probe/build_daily_page.py
                └─ mockups/v4/daily.html   （数据以 const DATA 内联，54 KB）
```

重新生成：

```powershell
python -u probe/build_heatmap.py      # 先从 API 刷新 posts.json（站点有新文章时）
python -u probe/build_daily_page.py   # 再生成 daily.html
```

## 三个坑

1. **同一天有多篇**。早期批量导入造成 16 个重复日期，最早几天每个日期都有 `Day 000` 和 `Day 001` 两条、甚至两条同名 `Day 001`（不同 slug）。第一版按「一篇一行」渲染，屏幕上连着出现四行 `04-09 周三`，像数据坏了；改成**一天一行 + Day chip**，同名同号的重复帖只留一个 chip。
2. **`html{scroll-behavior:smooth}` 会让截图脚本读到的 `scrollY` 是 0**。`location.hash` 跳转是动画的，`Math.round(scrollY)` 立刻读回来还是 0，截出来永远是页首。要截中间段落，先把它关掉：
   ```js
   document.documentElement.style.scrollBehavior='auto';
   document.getElementById('m2026-08').scrollIntoView();
   ```
3. **标题本身就是 `2025-04-09 Day 001`**，所以不能再单独显示「日期 + 星期 + 标题」三列 —— 三列说的是一件事。改成日期/星期各一列（窄的 mono），第三列只放 `Day NNN` chip；标题不是标准格式的 25 篇（如「好多天没有记录了」）用浅色正文 chip 原样显示。

## 刻意保留的空洞

- **Day486（2026-08-30）、Day487（2026-09-02）在站点上是 404**，API 列表里也没有这两条 —— 时间轴上它们表现为「留白」，没有编造。
- 72 天留白是真实断更，不是渲染缺失；热力条与时间轴的空白一一对应。

## 与另外两个页面的关系

- 首页记录区（`#journal`，固定滚动的那段）末尾加了「按天翻看全部记录 ↗」→ `daily.html`。
- `courses.html` 的导航「记录」指 `daily.html`；`daily.html` 的导航「课程」指 `courses.html` —— 两个二级页互为兄弟。
- 上线到 Halo 主题时：这份数据同样打成 `assets/data/posts.json` 随主题发，模板只用循环渲染，不需要后端接口。
